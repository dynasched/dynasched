Direct the scheduler to separate from the current

[allow-run-as-root]

Allow execution as root **(STRONGLY DISCOURAGED)**.

Running as root exposes the user to potentially catastrophic file
system corruption and damage — e.g., if the user accidentally points
the root of the session directory to a system required point, this
directory and all underlying elements will be deleted upon job
completion, thereby rendering the system inoperable.

It is recognized that some environments (e.g., containers) may require
operation as root, and that the user accepts the risks in those
scenarios. Accordingly, one can override DynaSched's run-as-root
protection by providing one of the following:

* The "--allow-run-as-root" command line directive

* Adding **BOTH** of the following environmental parameters:

     * "DSCHED_ALLOW_RUN_AS_ROOT=1"

     * "DSCHED_ALLOW_RUN_AS_ROOT_CONFIRM=1"

Again, we recommend this only be done if absolutely necessary.

[report-pid]

Print out dsched's PID on stdout ("-"), stderr ("+"), the pipe whose
file descriptor is given (an integer), or a file (anything else). A
file is removed when dsched exits.
#
[report-uri]

Print out dsched's URI on stdout ("-"), stderr ("+"), the pipe whose
file descriptor is given (an integer), or a file (anything else).
#
[keepalive]

Pipe for dsched to monitor - dsched will terminate upon its closure.
While the pipe is open, dsched ignores the first termination signal.
#
[debug]

Syntax: "--debug"

Show debug output: set dsched's verbosity to 10, unless a level was
already set by the dsched_verbose MCA parameter, and report dsched's
exit status as it exits.
#
[tmpdir]

Define the root location for the scheduler's session directory tree

See the "Session directory" HTML documentation for additional details
about the DynaSched session directory.

[controller]

A required argument is passed to the "--controller" directive to
specify how to connect to the system controller
(e.g., "--controller pid:12345").

Supported options include:

* "pid:<arg>": provides the PID of the target controller. This can
  be given as either the PID itself (arg = int) or the path to a file
  that contains the PID (arg = "file:<path>")

* "file:<path>": provides the path to a PMIx rendezvous file that is
  output by PMIx servers — the file contains all the required
  information for completing the connection

* "uri:<arg>": specifies the URI of the controller, or the name of
  the file (specified as "file:filename") that contains that info

* "ns:<arg>": specifies the namespace of the controller

* "system": exclusively find and use the system-level controller

* "system-first": look for a system-level controller, fall back to
  searching for an available controller the command is authorized
  to use if a system-level controller is not found

Examples:

   dsched --controller file:dvm_uri.txt

   dsched --controller pid:12345

   dsched --controller uri:file:dvm_uri.txt

   dsched --controller ns:prte-node1-2095

   dsched --controller pid:file:prte_pid.txt

[hostfile]

Name the hosts the scheduler allocates in a file, one host to a line:

   node01 slots=8
   node02 slots=8
   # a comment
   node03

A host given no "slots=" count has one slot, and a host named more than
once has the slots of every line that names it. A "max_slots=" entry is
accepted and ignored: the scheduler allocates whole nodes.

When the scheduler is attached to a system controller, the nodes it
allocates are the controller's. A hostfile then does not add to them:
it limits them to the ones it names, and a "slots=" count it gives is
the most of that node's slots the scheduler allocates. "--hostfile" can
be given more than once, and with "--host".
#
[host]

Name the hosts the scheduler allocates as a comma-delimited list, each
host optionally followed by its number of slots:

   dsched --host node01:8,node02:8,node03

A host given no count has one slot, and a host named more than once has
the slots of every time it is named.

When the scheduler is attached to a system controller, the nodes it
allocates are the controller's. A host list then does not add to them:
it limits them to the ones it names, and a count it gives is the most of
that node's slots the scheduler allocates. "--host" can be given more
than once, and with "--hostfile".

The dsched_default_hosts MCA parameter takes a list in the same form,
and is used only when there is no system controller and neither
"--host" nor "--hostfile" is given.
#
[bad-host-list]

A list of hosts cannot be used:

   From:   %s
   List:   %s
   Reason: %s

A list names hosts separated by commas, each optionally followed by a
colon and its number of slots - for example "node01:8,node02". See
"dsched --help host".
#
[bad-hostfile]

A hostfile cannot be used:

   File:   %s
   Line:   %d
   Reason: %s

Each line names one host, optionally followed by "slots=<count>". See
"dsched --help hostfile".
#
[controller-nodes]

The scheduler could not learn the nodes of the system controller it
attached to:

   Controller: %s
   Reason:     %s

The scheduler allocates the nodes the system controller holds, so it
cannot run without knowing them.
#
[hosts-not-in-dvm]

Some of the hosts given to the scheduler are not nodes of the system
controller it attached to, and will not be allocated:

   Controller: %s
   Hosts:      %s

With a system controller, "--host" and "--hostfile" can only limit the
scheduler to some of the controller's nodes.
#
[no-nodes]

The scheduler has no nodes to allocate, and will refuse every
allocation request.

   Nodes taken from: %s

Name the nodes with "--host" or "--hostfile", or in the
dsched_default_hosts MCA parameter, or start the scheduler where it can
attach to a system controller.
#
[bad-controller]

The value given to "--controller" cannot be used:

   Value:  %s
   Reason: %s

The value names the system controller in one of these forms:
"pid:<pid>", "pid:file:<path>", "file:<path>", "uri:<uri>",
"uri:file:<path>", "ns:<namespace>", "system" or "system-first".
See "dsched --help controller" for what each means.
#

options.
